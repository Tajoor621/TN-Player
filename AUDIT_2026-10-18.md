# TN-Player source, feature and delivery audit — 18 October 2026

Baseline: `54c221b4ef1b76815f20e5bdb9f5c8c5045b1d87`. Scope: Kotlin UI/playback/storage/security/subtitle/widget/worker source; manifest and Android resources; Gradle/wrapper/R8; unit and device tests; CI and APK/Pages publication scripts; public feature/privacy/license documents and brand consumers. Generated downloads were treated as deliverables, not source. This is a source/build review, not a penetration test or certification of every device/codec.

## Assessment

**Provisional engineering rating: 7/10**, subject to this revision's CI results recorded in VALIDATION.md. This qualitative rating weights functional core/data safety most heavily. It is not a measured performance score. A 10/10 production claim would conceal known feature, distribution and physical-device gaps.

| Area | Assessment | Evidence / decision |
| --- | --- | --- |
| Playback architecture | Strong core | One service owns ExoPlayer, audio focus, notification and session commands; the UI uses MediaController. No second competing playback engine added. |
| Storage/data safety | Good, with provider limits | Confirmed deletion, staged verified copies/moves, source recheck before move deletion, encrypted journal, bounded ZIP extraction and previewed backup merge. SAF cannot provide an atomic source compare/delete guarantee. |
| Privacy | Good local-first default | No telemetry/account/ad SDK; narrow FileProvider; disabled OS backup; network references and checkpoints encrypted. New saved caption text/URI/names use authenticated encryption and opaque HMAC filenames. |
| UI/accessibility | Improved, needs hardware QA | New user identity integrated across consumers; themed/legacy/adaptive icon resources; captions support font scaling and bounded layout; gestures remain off under touch exploration. Screen pinning and large-font layouts need OEM checks. |
| Feature coverage | Incomplete | Core playback/library/file operations are real. Universal software codecs, vault/app lock, Cast/DLNA, authenticated shares/nearby transfer and custom PCM DSP are not implemented. |
| Distribution | Release blocker remains | Debug APK publication is verified, but stable production signing, current Play target/toolchain and complete dependency notices are still release work. |
| Performance evidence | Insufficient for promised numbers | MediaStore scanning and metadata reads are off the UI thread with bounded display pages. Launch/seek/memory/thermal/battery targets have not been measured on representative devices. |

## Findings implemented in this revision

| Priority | Finding | Implemented correction |
| --- | --- | --- |
| High usability | Imported timed captions and offsets vanished when PlayerActivity finished or the process died. | Atomic encrypted per-file caption sessions, up to ten retained sessions / 32 MB; URI/name/text/delay/rate are private. Restore never opens a media URI or starts playback. Failed encryption keeps the old committed record. |
| Medium correctness | Choosing embedded tracks while the external overlay was active could leave the overlay covering the selected embedded track. | Explicit switch confirmation removes the saved external association; Cancel retains it. Native and timed subtitle modes remain distinct. |
| Medium launch safety | Oversized stream names/URLs or playlist metadata could exceed Android intent limits before the player could reject them. | Bounded input fields, title/MIME caps and a 1,000-file/100,000-character playlist budget, checked before launch and on receipt. Invalid input is rejected without starting playback. |
| Medium coverage | Subtitle speed correction was missing; delay alone cannot repair frame-rate drift. | 50–200%, steps of 0.1%, shared timing transformation for visible cues, cue navigation and SRT export. Export refuses adjusted timelines outside the import range instead of silently truncating. |
| Medium parser | WebVTT NOTE/STYLE/REGION metadata could be mistaken for cue content; malformed timing arrows could be skipped silently. | Metadata blocks are skipped and invalid timing arrows rejected; regression fixtures verify behavior. |
| Medium accessibility/gesture | Incremental caption gesture deltas could drift after reaching a size/position limit; sides and double-tap behavior were fixed. | Gesture changes derive from the start value; selectable volume/brightness sides and seek/play-pause double tap. TalkBack suppression retained. |
| Medium player UI | No optional clock, battery or remaining-time display. | Opt-in overlays, unknown-duration/battery handling, one-second status refresh and lifecycle cancellation. No extra battery permission. |
| Medium identity | Launcher used an old logo; no density PNGs or themed monochrome layer. | Exact user upload retained; separate full wordmark and emblem; mdpi–xxxhdpi PNGs, Android 8+ adaptive and Android 13+ monochrome resources; toolbar/settings/widget/shortcuts/web/README consumers updated. |
| Documentation | Help and status still described older subtitle/gesture behavior. | Updated help, feature comparison, branding provenance and test plan; old audit remains preserved. |

## Remaining priorities

1. **Production distribution:** migrate compile/target/toolchain coherently to current Play requirements, validate API 35/36 edge-to-edge/audio-focus/foreground-service behavior, configure an owner-controlled signing key and test upgrade installation. The requested API 21 minimum is retained; target 34 is still a development baseline. No signing secret has been committed.
2. **Downloads:** replace Android DownloadManager with an app-owned HTTPS download/scheduler pipeline, including redirect validation, cancellation, partial-file recovery and integrity checks. Existing backend remains in place with progress/retry/removal; HTTPS validation alone does not close the official backend risk guidance.
3. **Native formats/DSP:** select and license-review a maintained codec backend; validate real codec/container corpora, ABI size and 16 KB alignment before claiming universal playback. Add bounded audio delay/boost/limiting with clipping tests. Device EQ bands are not guaranteed ten-band DSP.
4. **Security features:** build an authenticated encrypted vault/app lock with recovery/export/key-loss behavior and independent review. Hiding files or enabling screen pinning is not a private vault.
5. **Network ecosystem:** authenticated SMB/SFTP/WebDAV clients, explicit local transfer sessions, Cast/DLNA capability handling and adaptive offline caching require working clients, connection lifecycle and physical-network tests.
6. **Subtitle completeness:** native styled/image/SAMI/Teletext fixtures, native sidecar persistence, simultaneous external tracks, custom fonts and provisioned online subtitle API remain separate work. Plain JSON library backups intentionally exclude caption text and network secrets.
7. **Maintainability/evidence:** MainActivity/PlayerActivity are still large and should be split by feature with navigation tests; benchmark 50k-file libraries and test SD/USB providers, interrupted writes, Bluetooth/car controls, low memory and accessibility on physical Samsung hardware.

## Acceptance evidence

New unit tests exercise authenticated caption persistence, fresh-store restoration, tampering/wrong keys, failed-write retention, atomic backup recovery, quota pruning, rate transformation, WebVTT metadata and settings backup. Native tests verify caption visibility, timing/rate changes, reopening the player, clock/battery/remaining time and double-tap pause. Existing external force-stop tests now also verify encrypted caption restoration. Build/lint/release and API 28/34 results must be green before main integration/publication.
